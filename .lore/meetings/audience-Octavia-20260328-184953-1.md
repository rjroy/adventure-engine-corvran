CORVRAN VISION FOUNDATION PRINCIPLE
Meeting: audience-Octavia-20260328-184953-1
Date: 2026-03-29
Participants: User, Octavia (Steward)

SUMMARY

The user recognized that the existing five design principles were missing a foundational layer. Discussion surfaced a concern about how enrichments like background images, panel systems, NPC agents, and rule modules should relate to the core application. The conversation revealed that the five principles described *how the system behaves* but never named *what it's all for*. The core principle—that everything the application does serves collaborative storytelling—was baked into the project name and vision text but never stated explicitly. This left the design vulnerable to feature creep where tools become the center rather than servants of the story.

The user and Octavia worked backward from concrete examples. Background images help tell the story but aren't the story; panels display information but aren't decisions; rule systems teach judgment but don't replace it. Each existed in a category that needed a name. The unnamed principle emerged: tools are additive, not central. The story is the product. When a feature starts accumulating its own requirements independent of storytelling, it has crossed from tool to center.

The foundational principle was named as Principle 0: "The Story is the Product." This principle provides the litmus test for all other design decisions and the integration depth of future systems. The six-principle structure now reads: Principle 0 names what the center is. Principles 1–5 describe how to behave around it. The vision document was updated to reflect this structure and approved for adoption.

DECISIONS

1. Added Principle 0 ("The Story is the Product") as the foundational design principle
2. Principle 0 serves as the integration depth test: if removing a feature leaves no story, it's core; if it leaves a less rich story, it's a tool on the table
3. Vision document status changed from draft to approved
