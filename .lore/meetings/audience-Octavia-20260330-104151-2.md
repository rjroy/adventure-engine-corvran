MEETING NOTES: Adventure Creation & System Integration Review

Session reviewed the adventure creation flow brainstorm and adventure system integration spec. Identified and resolved four previously open questions about file access, naming conventions, API design, and freeform handling. Confirmed that REQ-SYS-5 in the integration spec contained a bad requirement (adventure.md read-only) that contradicted the project vision; corrected the spec to state all adventure files are fully read/write for both AI and player with no restrictions.

Key decisions finalized: The creation flow follows Option C (middle path) with a lightweight pre-flight form containing system picker, concept text field, and name field—faster than full session zero conversation but more informed than minimal setup. Adventure directory names are slugified from player-chosen display names, with the display name stored in adventure.md frontmatter. System selection should be driven by a new API endpoint returning available systems rather than hardcoded frontend options. Plugin manifest format simplifies to use singular `alias` field plus `description` for dynamic UI generation. Adventure lobby displays name, system badge, concept snippet, character name (if available), last-played timestamp, and sorts by recency with new adventures at the top. Deletion remains deferred as a separate safety concern.

Artifacts: adventure-creation-flow.md brainstorm updated with resolved questions capturing reasoning behind each decision, and implementation considerations expanded to include manifest simplification details. adventure-system-integration.md spec updated to remove read-only constraint from REQ-SYS-5 and strike "write protection" from deferred section. Bootstrap prompts verified as requiring no downstream changes.

Brainstorm is self-contained and ready to drive a specification commission. No open items remain.
