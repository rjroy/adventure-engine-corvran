**MEETING NOTES: Dynamic Mood System Brainstorm**
Date: 2026-03-30 | Participant: Octavia

**Summary**

Completed brainstorm for a dynamic mood system for Corvran that changes both color palette and background image during gameplay. The system allows the GM to call a `set_mood(description)` tool, triggering atmospheric shifts visible to the player. Worked through six proposals evaluating different implementation approaches: text markers vs. MCP tools, hue sourcing (GM parameter vs. image extraction), color architecture, persistence strategy, and frontend application. Resolved design questions and unified on an image-first approach where the generated background image is the source of truth for both color palette and atmosphere.

**Recommended Direction**

The system generates atmospheric images via Replicate (FLUX Schnell, ~1s, $0.003 per image) from the GM's scene description prepended with an `art_style` field stored in `adventure.md` frontmatter. The backend extracts the dominant color from the generated image, derives an OKLCH hue angle, and emits a single `mood` SSE event containing hue, description, and image path. The frontend applies the hue by rotating the existing CSS palette variables while preserving lightness and chroma relationships, and displays the image at low opacity as atmospheric texture. Mood state persists to `adventure.md` frontmatter (`mood_hue`, `mood_description`, `mood_image`). On page load, the adventure detail endpoint includes `currentMood`, and the frontend applies it before rendering messages. Image generation failure falls back to keyword-derived hue from the description (or neutral hue if no keyword matches).

**Key Decisions & Reasoning**

- **Tool over text markers**: MCP tool is structurally enforced (dice tool pattern precedent), eliminating format drift issues with embedded markers
- **Image-first color sourcing**: Generated image guarantees color-image matching; no hue parameter on tool removes instruction burden from GM
- **CSS-based palette rotation**: Existing variable architecture (`@property`, `color-mix()`) handles derivation automatically; no new color math infrastructure needed
- **Mood as meta tool**: SSE event is `mood` type, not `tool_use`, keeping atmospheric machinery invisible in chat narrative
- **Persistent state**: Mood stored in frontmatter satisfies "Markdown is Memory" principle; no Replicate call on page reload
