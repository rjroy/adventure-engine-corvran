**Meeting Notes: Recap/Compaction: V1 Spec vs Brainstorm Approach 3**

Discussed concerns about scene boundary detection in the adventure engine's history compaction system. The V1 spec's approach (JSON archiving with configurable retention) was deemed overly complex. Converged on a three-trigger design that sidesteps automatic scene detection: character threshold triggers system-managed compaction (safety net), GM receives a tool to trigger compaction at narrative moments they judge as natural, and player gets a recap button for manual control. Story structure guidance to the GM replaces algorithmic scene detection.

Finalized the compaction mechanism: on any trigger, move `history.md` to `past/scene-NNN.md` (sequential numbering, human-readable archive), call Haiku to produce a narrative recap, and save the recap as the new `history.md`. Applied the same pattern generically to `world.md` with lighter compaction thresholds (light trim and consolidation rather than aggressive summarization). Confirmed the current prompt assembly already reads `history.md` directly, so the GM automatically receives the recap context on its next turn without additional engineering.

Created `.lore/brainstorm/compaction-system.md` capturing the three-trigger design, archive structure, and generic applicability to both history and world files. This brainstorm will serve as input for the next spec document, which can now focus on implementation details (threshold defaults, Haiku prompt wording, `past/` directory conventions) rather than design questions.
