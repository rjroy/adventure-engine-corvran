**MEETING NOTES: Corvran MVP Scope Design**

Discussion focused on narrowing the MVP scope for the AI-powered RPG session engine. The core question was whether adventure selection should be included as a feature or hardcoded as an assumption. Initial proposal deferred selection UI to avoid "bending over backwards," but user pushed back that adventure selection is a simple feature, not worth skipping just to defer. Team consensus settled on including a minimal adventure selection interface: daemon lists available adventures, web client shows a list (or skips to conversation if only one exists). No creation, deletion, or metadata editing in MVP.

Secondary discussion addressed RPG system selection and how it integrates with the MVP. Determined that system selection can be hardcoded at the daemon level by passing Corvran and Daggerheart system plugins to the Agent SDK session runner. RPG system choice is not an application-level concept in the MVP; the AI game master reads from available documentation and infers system from character sheets and gameplay. This design made explicit the relationship between Principle 5 (system-agnostic) and Principle 2 (teach, don't code): agnosticism emerges naturally from refusing to hardcode rules.

RPG system selection was identified as a deferred design question, not eliminated. When adventure manifests are introduced (beyond MVP), specifying which plugins to load becomes a natural configuration field. For now, both systems are always available.

**Decisions Made**

Adventure selection included in MVP. Daemon provides a simple list endpoint; web client shows adventure list or skips directly to conversation if one adventure exists. No creation or deletion UI.

RPG system plugins hardcoded in daemon. Corvran and Daggerheart system docs passed to Agent SDK at session startup. System choice inferred by AI from context, not specified by daemon.

Principle relationship clarified: Principle 5 (system-agnostic) is emergent from Principle 2 (teach, don't code). Engine is agnostic because it refuses to encode rules, not because of explicit architecture.
