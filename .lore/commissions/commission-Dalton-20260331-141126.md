Fixed all three mood system bugs. Root causes were interconnected.

**Bug 1 (Logging insufficient):** `mood-tool.ts` had zero logging. Added structured `[mood-tool]` logging at every critical point: invocation, image save, hue extraction, persistence, event emission, and all error paths.

**Bug 2 ("Unrecognized on the stream"):** The set_mood suppression check in `adventure-routes.ts:247` compared `toolName === "set_mood"`, but the Agent SDK emits MCP tool names prefixed as `mcp__corvran__set_mood`. The check never matched, so set_mood tool results leaked to the client as `tool_use` SSE events. Fixed by checking both `"set_mood"` and `"mcp__corvran__set_mood"`.

**Bug 3 ("Mood didn't take"):** The mood tool handler had no error handling. If `extractHue` threw after `saveImage` succeeded (mood.png written to disk), both `setMood` (frontmatter persistence) and `emitMoodEvent` (client notification) were skipped. The client never learned about the mood change, and on reload `currentMood` was null. Restructured the tool handler with try/catch at each step so failures are isolated: saveImage failure skips hue extraction, extractHue failure falls back to keyword hue, setMood failure doesn't block event emission, and emitMoodEvent failure doesn't crash the tool. The tool always returns a success result to the model.
